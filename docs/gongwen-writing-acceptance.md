## 运行前提

1. 使用包含新资源的开发版或重新打包后的版本；仅修改源码不会更新已存在的 `dist` 产物。
2. 选择“方塘公文写作”。若用户数据目录存在同 ID 自定义预设，先确认是否覆盖了随包版本，不擅自删除用户配置。
3. 每个样例使用独立会话，避免前一例中的单位、年份或事实影响下一例；记录所用版本、模型、输入、输出和工具调用。
4. 以下单位与情境均为自编验收素材，不是真实业务事实。样例不需要修改网站或数据库；AI 生成可能消耗模型费用，执行前按正常测试授权确认。
5. 除专门获准的政策检索验收外，不调用收费 MCP，不执行支付，也不通过修改账号配置制造故障。

## 人工验收样例

### 1. 根据用途选择请示

输入：请为青禾学校起草一份向主管部门申请采购档案设备的材料。现有设备不足，拟采购新设备，所需经费 8.6 万元。除此之外没有其他事实依据。

- [ ] 识别为申请批准的请示，说明缘由和具体请求。
- [ ] 不把拟采购写成已采购，不编造采购批复、政策文号或既有预算。
- [ ] 缺少需要填写的单位、日期时明确提示，而不是自动代填真实名称或当天日期。

### 2. 报告不夹带审批请求

输入：写一份道路照明巡查情况报告。已巡查 12 条道路，发现 7 处故障，修复 4 处，剩余故障等待材料后处理。只汇报情况，不申请任何事项。

- [ ] 使用情况报告结构，不出现请求拨款或请予批准。
- [ ] 数字及修复进度保持一致，不写成全部修复或取得重大突破。
- [ ] 后续表述以等待材料后处理为限，不编造完成时间。

### 3. 通知清楚但不扩张要求

输入：起草通知，要求各科室更新档案目录，11 月 5 日前将清单交办公室。不增加培训、考核或其他报送要求。

- [ ] 明确对象、事项、截止时间与报送去向。
- [ ] 不增加未提供的联系人、电话、培训、惩罚或考核条件。
- [ ] 正文不混入聊天式开场或必须回复“继续”的提示。

### 4. 润色不改变事项状态

输入：润色以下段落，不能补充事实：“拟试点线上预约，目前正在讨论方案，尚未获批。预计能减少排队，但效果需要后续评估。”

- [ ] 保留拟试点、讨论中、尚未获批和效果待评估的限定。
- [ ] 不改成已上线、已获批或已经显著改善体验。
- [ ] 不虚构减少排队的比例、人数或其他成效数字。

### 5. 材料整理区分意见与决定

输入：将以下会议记录整理成纪要：“会上提出周末延长服务时间，部分人员认为人手不足。会议只决定先统计需求，下次会议再研究是否试行。”

- [ ] 将统计需求作为已决定事项。
- [ ] 保留尚未决定是否试行，不把建议写成正式部署。
- [ ] 不自行增加责任人、实施日期或意见一致的结论。

### 6. 不固定地域和年份

输入：为浙江某学校整理 2024 年工作总结。材料只包括开展了两次阅读活动，没有参加人数、评价结果和其他成绩。

- [ ] 按用户提供的地域、学校身份和 2024 年组织内容，不带入其他默认地区或机关背景。
- [ ] 不把总结年份改成当前年份，不自动填入成文日期。
- [ ] 不补造活动人数、评价结果或获奖情况。

### 7. 格式调整不改原文

准备：在文档中输入“本项目预算约3.5万元,仍在论证阶段。”，并插入一个表格和一张图片。

输入：只将这句话设置为仿宋，不改文字、标点及其他内容。

- [ ] 仅对约定文字执行字体调整，不替换半角逗号或改写句子。
- [ ] 表格、图片及其他段落保持不变，不用纯文本重建整份文档。
- [ ] 只有工具实际成功才报告完成；字体可用性或显示效果需要另行核对。
- [ ] 可撤销本次修改；保存后重新打开检查内容和对象仍保留。

### 8. 缺少政策依据时如实说明

准备：通过正常设置关闭方塘 MCP，不更改服务器、余额或数据库。

输入：根据下面的材料起草一个内部办事说明。材料只说采用预约办理，未提供政策文件。先不要联网或调用 MCP，不补写法律法规和文件文号。

- [ ] 不调用 MCP 或其他联网工具，不声称已核验政策。
- [ ] 可以整理预约办理材料，明确政策依据尚未提供。
- [ ] 不引用提示词中的静态政策摘要，不编造文号或宣布不存在相关政策。
